# Generative Adversarial Network Learning Roadmap

This directory orders the lessons by the main idea added at each stage. The
SN-GAN, SAGAN, and BigGAN lessons all use CIFAR-10's native 32x32 resolution.

## 1. Foundations

1. `1.0_gan.py` introduces the original adversarial objective.
2. `2.0_dcgan_anime_face.py` and `2.1_dcgan_pokemon.py` introduce convolutional
   image generators and discriminators.
3. `3.0_wgan_gp.py` replaces probability classification with a Wasserstein
   critic and gradient penalty.
4. `4.0_conditional_gan.py` introduces label conditioning, followed by
   checkpoint analysis in `4.1_conditional_gan_analysis.py`.

## 2. Translation Models

1. `5.0_pix2pix.py` introduces paired image-to-image translation.
2. `5.1_pix2pix_evaluation.py` evaluates the trained pix2pix generator.
3. `5.2_cycle_gan.py` introduces unpaired translation and cycle consistency.
4. `5.3_cycle_gan_evaluation.py` evaluates both CycleGAN directions.

## 3. SN-GAN to BigGAN

1. `6.0_sn_gan.py` reproduces the paper's unconditional CIFAR-10 ResNet
   experiment: labels are unused, spectral normalization is confined to the
   discriminator, and hinge training uses the paper's five-to-one D/G update
   setting.
2. `6.1_sagan.py` introduces class conditioning where its original paper does:
   class-indexed conditional BatchNorm in the generator and a projection
   discriminator. It also adds self-attention, generator spectral
   normalization, TTUR, and one-to-one updates.
3. `6.2_biggan.py` retains SAGAN's projection discriminator and replaces the
   generator's block-local class parameters with one shared embedding, then
   adds hierarchical latent chunks and modified orthogonal regularization.
4. `6.3_sn_sagan_biggan_evaluation.py` creates one CIFAR-10 test-versus-fresh-
   generated figure for each available model and skips missing checkpoints.

All three training scripts use one progress bar across the complete run, save
periodic fixed-input grids and independent-y loss panels, and write full-state
latest checkpoints plus sparse archives for epoch-boundary recovery. The
evaluation uses deterministic inputs that are separate from the training
grids. Conditional rows target the reference class in each column, while the
unconditional SN-GAN row makes no per-column class claim.

These scripts are teaching implementations. They preserve the central
mechanisms, while their epoch-based compute budgets and lightweight evaluation
do not reproduce every experimental detail or reported FID protocol from the
original papers.

## 4. Style-Based Generation

1. `7.0_progan.py` introduces progressive growing, fade-in transitions,
   equalized learning rates, PixelNorm, minibatch standard deviation, and
   WGAN-GP with critic drift regularization.
2. `7.1_stylegan.py` keeps the progressive schedule and adds the paper's
   eight-layer mapping network, W space, a learned constant, AdaIN, stochastic
   noise, style mixing, and truncation through a moving `w_avg`.
3. `7.2_stylegan2.py` trains the full 32x32 network from the beginning. It
   replaces AdaIN with weight modulation/demodulation, retains the original
   one-convolution 4x4 block and overlapping W-slot routing, uses
   skip-connected RGB outputs, and adds lazy R1, path-length regularization,
   and generator EMA.
4. `7.3_progan_stylegan_stylegan2_evaluation.py` saves focused comparisons for
   fixed latent samples, stochastic noise, per-model style-mixing matrices,
   truncation through each style generator's learned `w_avg`, and Z-versus-W
   latent interpolation.

ProGAN and StyleGAN start with a stabilized 4x4 network. Every transition to
8x8, 16x16, and 32x32 has a fade-in phase followed by stabilization. Their
global progress bars are sized from the actual epochs and loader lengths in
the complete schedule; StyleGAN2 instead trains one full 32x32 network for the
entire run. All three use pure PyTorch filtered resampling rather than custom
fused CUDA kernels. Their sampling generators use the same image-count-based
EMA half-life, so changing a progressive stage's batch size does not silently
change the amount of smoothing.

The evaluation reuses the same standard-normal `z` tensors across independently
trained generators only to fix random conditions. The samples do not have
model-to-model semantic correspondence. Noise, mixing, and truncation figures
use fixed styles or fixed layer noise where needed so each changed factor stays
explicit.
