# VAE Variant Lessons

These scripts are algorithm lessons, not a production training framework.  A
lesson keeps its objective, gradient boundaries, inference path, and sampling
order in one readable file.  Repeated neural-network blocks and mathematical
primitives live in `dl_utils/vae/`; generic trainers, mixed precision,
compilation, distributed execution, and hidden hyperparameter search do not.

The variants after beta-VAE form four branches.  Their numbering expresses an
increment within a branch, not one universal historical upgrade chain.

## 1. Information Capacity and Total Correlation

| Lesson | Visible algorithmic increment | Main diagnostic |
|---|---|---|
| `1.2_beta_vae_train.py` | Multiply the complete sample KL by beta | distortion, rate, active dimensions |
| `1.3_beta_vae_analysis.py` | Deterministic reconstruction and cautious latent analysis | per-dimension KL, traversal, known-label alignment |
| `1.4_beta_tc_vae.py` | Add `(beta - 1) * TC_MWS` while retaining the ordinary VAE rate | MWS decomposition and its estimator-dependent offset |
| `1.5_factor_vae.py` | Estimate the same TC density ratio with a latent discriminator | VAE loss versus density-ratio discriminator loss |

The MNIST scripts expose the estimators cheaply but do not provide complete
ground-truth generative factors.  A semantic disentanglement claim needs a
controlled dataset, matched-rate comparisons, multiple seeds, and more than
one supervised factor metric.  TC reduction alone does not identify human
semantic axes.

## 2. Hierarchical Gaussian Latents

| Lesson | Visible algorithmic increment | Generation order |
|---|---|---|
| `2.0_hierarchical_vae.py` | `p(z2) p(z1|z2) p(x|z1)` and aligned conditional KL terms | sample `z2`, then `z1`, then pixels |
| `2.1_ladder_vae.py` | Replace the lower posterior network with a precision-weighted product of prior prediction and bottom-up evidence | unchanged |

The top Ladder posterior comes from bottom-up evidence alone.  It is compared
with `N(0,I)` in the KL but is not fused with that prior.  Free bits are
applied after each layer's batch-mean KL, and warm-up multiplies all layer KL
terms.  Both alter collapse incentives without guaranteeing that every layer
is useful.  Saved counterfactual grids replace the lower posterior by its
matching conditional-prior mean.

## 3. Discrete Tokenizers and Two-Stage Generation

| Lesson | Tokenizer | Frozen stage-two prior |
|---|---|---|
| `3.0_vq_vae.py` | one 8x8 learned VQ grid | PixelCNN `p(z)` |
| `3.1_vq_vae_2.py` | 4x4 top VQ plus conditioned 8x8 bottom VQ | `p(top) p(bottom|top)` |
| `3.2_fsq.py` | fixed finite scalar levels packed by mixed radix | the same PixelCNN interface |

VQ-VAE-2 combines hierarchy with vector quantization.  FSQ is a parallel
replacement for learned vector lookup, not the next VQ-VAE-2 version.  Every
tokenizer reports reconstruction, marginal entropy/perplexity, active codes,
and the fixed-length capacity upper bound where relevant.  High utilization
does not by itself imply useful or easily modeled tokens.  The compact
VQ-VAE-2 lesson deliberately reuses the preceding gradient-updated VQ block to
isolate the hierarchy increment; the original VQ-VAE-2 tokenizer used EMA.

Run stage one before stage two when inspecting the frozen boundary:

```bash
python genai/2.0_variational_autoencoder/3.0_vq_vae.py --stage tokenizer
python genai/2.0_variational_autoencoder/3.0_vq_vae.py --stage prior

python genai/2.0_variational_autoencoder/3.1_vq_vae_2.py --stage tokenizer
python genai/2.0_variational_autoencoder/3.1_vq_vae_2.py --stage prior

python genai/2.0_variational_autoencoder/3.2_fsq.py --stage tokenizer
python genai/2.0_variational_autoencoder/3.2_fsq.py --stage prior
```

## 4. Learned Reconstruction Metrics and Perceptual Compression

| Lesson | Bottleneck | Reconstruction metric | Adversarial path |
|---|---|---|---|
| `4.0_vae_gan.py` | Gaussian | jointly learned discriminator features | reconstructions and prior samples |
| `4.1_vqgan.py` | learned VQ | L1 plus frozen pretrained VGG features | PatchGAN, delayed hinge loss, adaptive last-layer weight |
| `4.2_kl_autoencoder.py` | weakly KL-regularized continuous grid | LDM-style element-summed NLL with the same VGG proxy | PatchGAN, delayed hinge loss, adaptive last-layer weight |

VQGAN directly extends the VQ-VAE tokenizer.  KL-AE is its continuous sibling
for a downstream latent model; it is not a mode switch hidden inside the same
lesson.  VAE-GAN is retained because it makes the earlier learned-similarity
idea and its three optimizer phases explicit.

The published VQGAN/LDM losses use LPIPS.  This repository uses pretrained
VGG16 features as a compact extra-package-free proxy and names the log accordingly.
The first real run may download the official torchvision VGG16 weights.
`--perceptual random` exists only to test the gradient path offline and must
not be reported as a perceptual metric.

VQGAN's stage-two Transformer completes unconditional generation:

```bash
python genai/2.0_variational_autoencoder/4.1_vqgan.py --stage tokenizer
python genai/2.0_variational_autoencoder/4.1_vqgan.py --stage prior
```

KL-AE only defines encode, deterministic reconstruction, latent scaling, and
decode interfaces.  Its unconditional generator belongs to the diffusion
series; a random-normal decoder output is only a prior-interface diagnostic.

## 5. Resource and Verification Contract

Defaults use MNIST or CIFAR-10 and compact networks intended for a single
GeForce RTX 4070 Ti 12 GB.  The 4.x defaults use batch 64; lower it before
changing the algorithm if local memory is tighter.  Default trainable module
sizes are small: VQ-VAE 1.19 M, VQ-VAE-2 2.61 M, FSQ 1.08 M, VQGAN AE
1.63 M, KL-AE 1.47 M, PatchGAN 1.25 M, PixelCNN 1.84 M, and Transformer prior
3.44 M parameters.  The frozen VGG feature extractor is additional.  No full
convergence claim can be made from a smoke test.

Every post-beta script accepts `--smoke-test`.  A smoke test checks tensor
shapes, one backward pass, quantizer index contracts, or alternating optimizer
boundaries without downloading datasets or pretrained weights.  For model
selection, treat per-epoch console values as training diagnostics and run a
fixed held-out protocol; additionally compare paired distortion, perceptual distance,
reconstruction-distribution quality, token/KL statistics, and the quality of
a matched-budget downstream prior.  Sharper adversarial reconstructions can be
less faithful to their inputs.
